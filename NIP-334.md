NIP-334
=======

Social Proofs (Bitcoin-Anchored Nostr Events)
---------------------------------------------

`draft` `optional`

This NIP defines kind `33444` for publishing cryptographic proofs that anchor Nostr events (profiles, notes, etc.) to Bitcoin transactions using Taproot key tweaking.

## Motivation

Nostr events are ephemeral by nature - relays can go offline, events can be deleted. By anchoring events to Bitcoin, users create permanent, verifiable proof that their identity or content existed at a specific point in time.

## Kind 33444: Social Proof

Kind `33444` is a parameterized replaceable event (per NIP-33) that stores proof of a Nostr event being anchored to a Bitcoin transaction.

### Tags

| Tag | Required | Description |
|-----|----------|-------------|
| `d` | Yes | Unique identifier: hex pubkey (profiles) or event ID (notes) |
| `p` | Yes | Hex pubkey of the identity being anchored |
| `e` | Yes | Event ID of the anchored Nostr event (kind 0, kind 1, etc.) |
| `c` | Yes | Commitment URI in TXO format: `txo:<chain>:<txid>:<vout>` |
| `t` | No | Hashtags for discovery (e.g., `blocktrails`, `immortalize`) |

### Chain Identifiers

| Chain ID | Network |
|----------|---------|
| `btc` | Bitcoin mainnet |
| `tbtc4` | Bitcoin testnet4 |
| `ltc` | Litecoin mainnet |

### Content

JSON object containing proof details:

```json
{
  "type": "profile" | "note",
  "txo": "txo:tbtc4:abc123...:0",
  "tx1": "<genesis_txid>",
  "tx2": "<anchor_txid>",
  "chain": "tbtc4",
  "dataHash": "<sha256_of_canonical_nostr_event>",
  "basePubkey": "<hex_pubkey_used_for_tweaking>"
}
```

| Field | Description |
|-------|-------------|
| `type` | Type of anchored content: `profile` or `note` |
| `txo` | TXO URI pointing to the anchor output |
| `tx1` | Transaction ID of the genesis transaction (optional, for 2-TX flow) |
| `tx2` | Transaction ID of the anchor transaction |
| `chain` | Chain identifier |
| `dataHash` | SHA256 hash of the canonical Nostr event (see Verification) |
| `basePubkey` | The x-only public key used as the base for tweaking |

## Cryptographic Method

This NIP uses [Blocktrails](https://blocktrails.org) P2TR key tweaking:

```
tweak = SHA256(nostr_event_hash) mod n
anchor_privkey = base_privkey + tweak
anchor_pubkey = base_pubkey + tweak × G
```

The anchor transaction output uses a P2TR address derived from `anchor_pubkey`, cryptographically committing to the Nostr event data without any on-chain data bloat.

## Verification

To verify a social proof:

1. **Parse the TXO URI** from the `c` tag to get chain, txid, and vout
2. **Fetch the anchor transaction** from a block explorer API
3. **Extract the x-only pubkey** from the P2TR output's scriptPubKey
4. **Fetch the original Nostr event** using the `e` tag
5. **Compute the canonical event hash**:
   ```javascript
   hash = SHA256(JSON.stringify([0, pubkey, created_at, kind, tags, content]))
   ```
6. **Derive the expected anchor pubkey**:
   ```javascript
   tweak = BigInt('0x' + hash) % CURVE_ORDER
   expected = basePubkey + tweak × G
   ```
7. **Compare**: The proof is valid if `expected == anchor_pubkey`

Note: When deriving from an x-only pubkey, try both y-parities (even and odd) as the original may have had either.

## Use Cases

- **Identity Proofing**: Prove your Nostr profile existed at a specific time
- **Content Timestamping**: Anchor important notes to Bitcoin for permanence
- **Attestations**: Third parties can anchor attestations about other users
- **Archival**: Create Bitcoin-backed snapshots of Nostr content
