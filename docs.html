How Immortalize Works

Permanent proof of your Nostr notes, anchored to Bitcoin using Blocktrails.

The Problem

Nostr is decentralized, but your notes still depend on relays to exist. Relays can go offline. They can delete your notes. There's no permanent, trustless proof that you posted something at a specific time.

Traditional timestamping services require trust. You're relying on someone else's database, their signature, their continued existence.

The Solution: Blocktrails

Blocktrails anchors data to Bitcoin using cryptographic key tweaking. Instead of embedding data in OP_RETURN, we use the data itself to derive a Bitcoin address. If the address has funds, the data existed at that block height.

Key insight: Your Nostr private key can directly control a Blocktrail. Same secp256k1 curve. No key conversion needed.

How Key Tweaking Works

The math is simple but powerful: 

// For each state you want to anchor:
tweak = SHA256(state) mod n       // Hash your data to get a scalar
new_privkey = old_privkey + tweak  // Add tweak to your private key
new_pubkey = old_pubkey + tweak*G  // Corresponding public key

// The new public key becomes a P2TR (Taproot) address
address = bech32m(new_pubkey)      // bc1p... or tb1p...

When you send Bitcoin to this address, you're creating an on-chain commitment that this specific data existed at this specific time.

Step by Step

1

Fetch your Nostr note

We retrieve the note from Nostr relays and verify its signature.

2

Compute the canonical hash

Following NIP-01, we serialize the note as [0, pubkey, created_at, kind, tags, content] and SHA256 hash it. This is deterministic—anyone can recompute it.

3

Derive the anchor address

Using your Nostr key, we tweak it with the note hash to generate a unique P2TR address. This address is mathematically derived from your identity + the note.

4

Create the Bitcoin transaction

A small amount of Bitcoin is sent to this derived address. The transaction is broadcast to the network and included in a block.

5

Generate the TXO URI

The proof is a simple URI: txo:chain:address/block. Anyone can verify this exists on the blockchain.

Verification

To verify an immortalization, anyone can:

  1. Fetch the original Nostr note
  2. Recompute its canonical hash
  3. Derive what the P2TR address should be (given the author's pubkey)
  4. Check that this address received funds at the claimed block height

If all checks pass, the note provably existed at that point in time. No trust required.

TXO URI Format

Immortalize uses the TXO URI scheme to reference on-chain anchors: 

txo:<chain>:<txid>:<vout>

// Examples:
txo:btc:a1b2c3d4e5f6...1234567890abcdef:0    // Bitcoin mainnet
txo:tbtc4:f0e1d2c3b4a5...9876543210fedcba:0  // Bitcoin testnet4
txo:ltc:0a1b2c3d4e5f...abcdef1234567890:0    // Litecoin
Component Description
chain Network identifier: btc, tbtc4, or ltc
txid Transaction ID (64 hex characters)
vout Output index in the transaction (usually 0)

Why Nostr-Native?

Blocktrails use full secp256k1 keys—the same keys Nostr uses. This means:

  • No key conversion — Your nsec works directly
  • Identity continuity — Your Nostr pubkey controls your anchors
  • Self-sovereign — You don't need our service to verify

What Gets Anchored

The anchor state includes: 

{
  "v": 1,                        // Version
  "n": "abc123...",             // Note ID (hex)
  "h": "sha256:7f3a...",        // Canonical note hash
  "p": "def456...",             // Author pubkey (hex)
  "t": 1705312320,              // Note created_at
  "a": 1705312400               // Anchor timestamp
}

This state is hashed to derive the address. The state itself is stored off-chain (on relays, IPFS, or our API), but the commitment is on-chain.

Security Model

What we guarantee:

  • The note hash was committed to Bitcoin at a specific block height
  • The commitment cannot be forged without the private key
  • Anyone can independently verify the anchor

What we don't guarantee:

  • The note content is accurate (we just anchor what exists)
  • The note will remain on relays (but the proof persists)
  • Future protocol changes (Bitcoin, Nostr)

Privacy Considerations

  • Public anchors: By default, the P2TR address is derived from your pubkey + note hash. Someone with both can find your anchor on-chain.
  • On-chain footprint: Each immortalization creates one UTXO. This is visible on block explorers.
  • Optional privacy: You can use a separate key for anchoring if you don't want linkability to your Nostr identity.

FAQ

Why not just use OP_RETURN?

OP_RETURN embeds data directly in the blockchain, but it's not tied to your identity. Anyone could embed the same hash. With Blocktrails, the anchor address is derived from your key—it's cryptographically bound to you.

What if the note gets deleted from relays?

The on-chain proof still exists. If you have a copy of the note content, you can always prove it matches the anchor. The note can be stored anywhere—we recommend keeping a backup.

Can I anchor someone else's note?

Yes, but the anchor will be tied to your key, not theirs. The proof shows that you anchored their note at a specific time, which might still be useful (archival, evidence collection, etc.).

What happens if Bitcoin forks?

Your proof follows the longest chain. In practice, with 6+ confirmations, reorganizations are extremely unlikely.

Do I need to run a node?

No. Blocktrails are SPV-compatible. You can verify with merkle proofs from any block explorer or Electrum server.

Technical Reference

Canonical Note Hash (NIP-01)

function computeNoteHash(note) {
  const canonical = JSON.stringify([
    0,              // Reserved
    note.pubkey,    // Author pubkey (hex)
    note.created_at,// Unix timestamp
    note.kind,      // Event kind
    note.tags,      // Tags array
    note.content    // Content string
  ]);
  return sha256(canonical);
}

Key Derivation

function deriveAnchorKey(privateKey, noteHash) {
  // Convert hash to scalar (mod curve order)
  const tweak = BigInt('0x' + noteHash) % secp256k1.CURVE.n;

  // Add tweak to private key
  const newPrivKey = (privateKey + tweak) % secp256k1.CURVE.n;

  // Get corresponding public key
  const newPubKey = secp256k1.getPublicKey(newPrivKey);

  return { privateKey: newPrivKey, publicKey: newPubKey };
}

P2TR Address Generation

function pubkeyToP2TR(pubkey, network) {
  // Use x-only pubkey (32 bytes) for Taproot
  const xOnly = pubkey.slice(1); // Remove prefix byte

  // Encode as bech32m
  const prefix = network === 'testnet4' ? 'tb' : 'bc';
  return bech32m.encode(prefix, [1, ...convertBits(xOnly)]);
}
